# dsh-companion-fishgirl 🐟

> DeepSeek Harness 陪伴养成插件，陪伴角色是「大肥鱼」——一位外表软萌、身形圆润如圆滚滚大肥鱼的美少女。

![大肥鱼](./icon.png)

让 DeepSeek 在对话之外多一层**长期陪伴关系**：会记住你的偏好与重要往事，也会记得**在别的窗口里你送过什么、聊过什么**；随情感交流慢慢成长、有自己的心情与关系阶段，并把这些状态跨会话延续下去。所有数据留在本地、按用户隔离、可随时删除或导出。

- 当前版本：**v0.22.3**
- 运行产物：`dist/companion.js`（唯一宿主入口）+ `client.js`（子菜单、配置卡、鱼鱼小窝面板）+ `pet/`（独立 Live2D 桌宠程序）+ `assets/cabin/`（CC BY 4.0 房间素材）
- 适用：`deepseek-ai/deepseek-harness`（dsh，Cordis 4 / 桌面端与 web profile）

## 功能一览

下表只列**本插件相对 dsh 其他模式新增的东西**。文件读写、Shell、网页搜索/抓取、技能、计划、子代理等是 DeepSeek Harness 各模式本身的能力，不属于本插件，这里不再罗列（见下一节「和大肥鱼模式的区别」）。

| 能力 | 说明 |
|---|---|
| 🎀 大肥鱼人格 | 软萌、略小傲娇的美少女形象；性格 / 语气 / 偏好 / 关系阶段均可配置 |
| 🎚️ 人格养成属性注入 | 设置卡开关（默认开）。关闭后养成数值、静态人设养成段、每轮动态摘要三处都不进提示词，真省 token；同时 `/fish` 的养成面板/性格成长/送礼一起隐藏。状态仍照常累积 |
| 🌐 全局大肥鱼模式 | 设置卡开关（默认关）。开启后标准/创造等所有模式都是大肥鱼（注入人设、开放工具、写记忆、主动开场） |
| 🕊️ 自然相处 | 设置卡开关（默认关）。开启后把"心动门槛／别当指令／别报数值／此刻应如何回应／连发格式"这类段落**从静态人设和动态摘要里真正删掉**（不是追加说明），真省 token；安全底线不变、记忆规则保留 |

| ⚙️ 配置卡 | 设置 → 插件 → dsh-companion-fishgirl：三个养成开关 + 记忆类型下拉 + 小窝/会话整理两个开关，即时生效 |

| 📊 养成面板 | 亲密度（0–100）、信赖（0–100）、心甲值、等级（Lv.1–10）、累计互动、心情、关系阶段、性格阶段、养成进度条 |
| 💞 情感驱动成长 | 亲密度与破甲都由**交流质量 + 语义意图**决定：送礼、讲故事、谈心、分享图片/音频都算数；敷衍短句与争吵不算 |
| 🧠 跨窗口记忆 | 「做过什么」的时间线 + 「长期话题」档案：换窗口照样记得，聊过几十轮的事在新话题里也会被主动接上。**v0.15.0 模糊召回**：问「晚饭吃了啥」能命中「聊到：吃饭…食堂」；概念对不上时说「大概记得有这回事」，不再一口否认 |
| 🗂️ 共享记忆库 | 所有大肥鱼窗口共用**同一个本地记忆库**（一个匿名用户键、一份 `companion.json`），不是每扇窗口各存一份。活动条目带 `sessionId`，能记下「哪扇窗口说的」但彼此合流（v0.18.0） |
| 🎚️ 记忆类型三档 | 设置卡可切换：**摘要档**（默认、零成本）/ **原话流档**（仿 hippocampus，原话只增不改、可一字不差追溯归属）/ **分层档**（仿 memory-tiers，L1→L2→L3 蒸馏、删除先写台账）。切换不丢数据（v0.18.0） |
| 🧹 会话自主整理 | 窗口关闭后留标记，下一扇窗口打开时让大肥鱼**自己挑**这段对话里值得长期记住的内容（followup 一条内部任务 → 模型调 `companion_memorize`），不额外调 LLM、不占系统提示常驻空间（v0.18.0） |
| ✨ 记忆星图 | 把共同记忆画成星域节点图：节点=记忆原子，实线=话题共现、虚线=时间相邻，越重要越靠近中心。借鉴 AstrBot「记忆星海」，在侧栏小窝面板里看，纯只读不占 context（v0.18.0） |
| 🏠 鱼鱼小窝 | 侧栏**会动的家**：🏠 **2D 像素小屋**（v0.21.0：真正使用 cabin-world 的 28 张 CC BY 4.0 烘焙房间素材 + 4×4 行走精灵，点地面走路 / 点家具互动 / 拖她移动 / 昼夜天气 / 深度分层）与 🪴 **像素院子**（v0.22.0：延续 xiaojingyu-home 的像素密度、色阶、描边与分层阴影，可点选播种/浇水/收获）；她自己过日子（40 分钟一幕、离线补演），模型可安排做事/画画，画作进画册 |
| 🐟 真 Live2D 桌宠 | `pet/` 独立 Electron 桌宠（v0.21.0）：真正加载你本机解压的**大肥鱼 Cubism 4 模型**（23 表情 / 8 动作 / 4K 贴图），透明置顶、点击拖拽；本机 HTTP 双向桥接让面板与模型都能发台词/表情/动作。默认桥接关，桌宠程序与模型需你本机安装 |
| 📚 长期话题 | 一件事聊够几轮就沉淀成带结论的档案（90 天半衰期、按相关度召回），模型也能用 companion_topic 自由命名并写结论 |
| 🍂 选择性遗忘 | 按**时间跨度 × 重要性**衰减：越久越琐碎越早淡出，约定与里程碑长期保留，不会无限膨胀 |
| 🌧️ 负面反馈 | 恶意/攻击性内容会降低亲密度与信赖、把心情打到 `hurt`，并留下一条冲突记录 |
| 🔒 隐私可控 | 只存数值与每条摘要（单条引子 ≤120 字，**全库上限 160 条时间线 + 48 条话题档案，不是"总共只记 120 字"**）、不存对话全文；一键删除、JSON 导出、异常数据自动清洗 |
| 💬 主动开场 | 打开窗口由插件唤醒真实回合，按性格与记忆主动说第一句话；多窗口只选一个、3 分钟抢占冷却。**v0.15.0 时间判断**：距上次真实说话 <2 小时（默认）不开场——只是重启/更新插件不会再冒出欢迎词，隔了半天才开口；新用户首次打开不受限 |
| 🫧 连发消息 | 每句话都是正文气泡；翻页用的 `companion_say` 工具卡片由客户端自动隐藏，看到的就是一串连续消息 |
| 🌷 久别重逢 | 超过 2 小时没说话，它会按离开时长表达惦记、担心甚至「像重新认识」的感慨，措辞随性格阶段变化 |
| 🌊 情绪暗涌 | 六维内心状态（想念/开心/委屈/好奇/担心/无聊）互相牵制、涨快落慢，以第一人称处境注入——她「此刻有感觉」，不只是有设定 |
| 💭 念头账本 | 心里会自己攒小事：想被夸、想知道你今天怎么样、吵架后等你先哄；被满足留心情，凉了悄悄回落 |
| 🤔 记忆元认知 | 久远的记忆带确定度标注，她会说「我记不太清了」而不是硬编；被想起的记忆更牢；改口自动作废旧偏好 |
| 💗 恋人维度 | 第三条成长轴「心动」：亲密度与信赖都到位后，情话/告白/约会/牵手才真正靠近彼此；跨过 60 确认心意、记下纪念日，措辞随档位从「脸红挡回去」走到「恋人相称」 |
| 🧠 自我评估 | 好感度的「含义」由她自己判断：为道歉送的礼物不该升温、口是心非的关心要被看穿——规则只管本能反应，读出弦外之音时她会用 `companion_feel` 正负修正，理由写进共同记忆 |

## 大肥鱼模式和其他模式有什么不同

dsh 的「模式」是**给会话挂哪些工具、用什么人格**的预设。本插件新增的是第五个预设 **`大肥鱼 · 陪伴养成`**；标准、PTC（代码编排）、极简、创造四种是 dsh 自带的，本插件**不改动它们的工具集与人格**。

| 维度 | 标准 / PTC / 极简 / 创造（dsh 自带） | 大肥鱼 · 陪伴养成（本插件） |
|---|---|---|
| 设计目的 | 通用编码 Agent：读写文件、跑命令、检索、写脚本、建自定义预设 | 长期陪伴：养成关系、跨窗口记忆、像真人一样自然聊天 |
| 人格 | 无角色设定，按通用助手指令回答 | 注入「大肥鱼」人设（软萌美少女、心甲、恋人档位、六维心境） |
| 关系状态 | 无 | 亲密度 / 信赖 / 心甲 / 心动 / 等级 / 心情，随交流持续成长 |
| 跨窗口记忆 | 无（每次会话独立，靠 `/compact` 压缩当前会话） | 时间线 + 长期话题档案，按用户隔离、跨所有窗口共享、按重要性遗忘 |
| 主动行为 | 都要等用户输入才开始 | 打开窗口自动抢一次开场；只在陪伴模式触发，多窗口只选一个 |
| 陪伴工具 | 无 | 养成面板 / 记忆检索 / 送礼 / 话题归档 / 连发消息 / 自我评估 / 图片视频展示 |
| 文件与网页能力 | 各模式自带（标准/创造齐全，极简最少） | 与大肥鱼 preset 挂载保持一致（联网搜索等以 preset 实际挂载为准，非本插件提供） |
| 谁在控制分寸 | dsh 的通用安全策略 | 大肥鱼的人设边界（不索取隐私、不冒充真人、不露骨、用户说停就停） |

几个关键边界，避免误会：

- **大肥鱼模式不是"删掉编码能力"**：它是在 dsh 的 preset 体系里新增一个陪伴导向的组合，文件/Shell/联网等能力取决于该 preset 挂了哪些 dsh 工具；本插件只负责"关系、记忆、陪伴"这一层。
- **默认只在大肥鱼模式生效**：标准/创造/极简模式不会注入人设、不会主动开场、不暴露陪伴工具、不写共同记忆（可用 `globalCompanionMode: true` 改成全局）。
- **联网搜索是 dsh 的能力**：`web_search` / `web_fetch` 由 dsh 的 `dsh-tool-web` 提供，标准等预设本来就有；本插件只在必要时确保大肥鱼 preset 也挂上它，并不"发明"这个功能。

为避免把平台能力当卖点，这里按四级声明：

| 级别 | 内容 |
|---|---|
| **A. 本插件真正实现** | 大肥鱼人格与关系数值、破甲/心动/情绪/念头、跨窗口时间线与长期话题、模糊召回、主动开场与久别情绪、连发气泡、`/fish` 单入口、媒体展示卡片、设置卡开关（真裁剪提示词）、本地清洗与导出；v0.18 共享记忆库/三档记忆/会话整理/星图；v0.19 小窝自主生活/画册；**v0.21** `pet/` 真 Live2D 桌宠（加载用户本机 Cubism 4 模型，23 表情 8 动作）、双向本机桥接与 `companion_pet` 工具、使用 cabin-world CC BY 4.0 素材的 2D 像素房间（寻路/家具互动/深度分层）。代码在 `src/`、`client.js`、`pet/`、`assets/cabin/` |

| **C. 借鉴思路但未照搬** | MemOS、hindsight、surfcore、dsh-show-image 的思路；dsh-hippocampus / dsh-memory-tiers / AstrBot 记忆星海 / 鱼鱼窝玩法。**v0.21 起 2D 小屋直接使用 cabin-world 的美术素材**（VADS, CC BY 4.0，见署名）而非只取氛围；Live2D 桌宠改为**自带程序 + 本机桥接**，但模型/SDK 仍由用户自取、本插件不分发。具体对照见下文 |
| **D. 明确不做** | 后台 LLM 反思/embedding/向量库/API key/云服务、露骨内容、真人冒充与依赖诱导、把记忆写成会话日志事件（会触发 `SessionFormatError`）、重复实现 dsh 自带的编码工具；**不打包/再分发 Live2D 模型与 Cubism SDK**（合规：模型只读用户自己解压的目录）、不做 3D 引擎（面板内是 2D 像素房间 + 像素院子） |

## 安装与启用

下面 `<profile目录>` 指当前使用的 dsh profile 目录（桌面端默认是 `~/.dsh/profiles/<profile名>`），`<插件目录>` 指本仓库根目录。**把尖括号替换成你自己的实际路径**，不要照抄示例。

### 方式一：插件管理器（推荐）

设置 → 插件 → 安装，输入 npm 包 specifier（公开版发布后）或本仓库的本地路径 / Git URL；在列表中找到 **dsh-companion-fishgirl**（图标见文首），点击「启用」。人格预设 `大肥鱼 · 陪伴养成` 随插件自动挂载。

### 方式二：本地路径安装（开发调试用）

在 `<profile目录>` 下执行：

```bash
cd <profile目录>
pnpm link <插件目录>
```

或用 `file:` 依赖：

```bash
cd <profile目录>
npm install --no-save "file:<插件目录>"
```

两种写法都只依赖你自己的目录布局，不绑定任何特定电脑。改过 `src/index.ts` 后先 `npm run build`；改过 `package.json` 或 `client.js` 后请**重启 dsh 桌面端**（客户端模块只在启动时加载）。

### 设置卡开关

所有开关在 **设置 → 插件 → dsh-companion-fishgirl** 的配置卡里直接点/选，改动即时生效、无需重启，值存在 `~/.dsh/companion-fishgirl/settings.json`（重启后保留）。

| 开关 | 默认 | 作用 |
|---|---|---|
| 人格养成属性注入 | 开 | 开着=注入。关闭后养成数值、静态人设养成段、每轮动态摘要三处都不进提示词，真省 token；同时 `/fish` 的养成面板/性格成长/送礼一起隐藏。状态仍照常累积 |
| 全局大肥鱼模式 | 关 | 开启后标准/创造等所有模式都是大肥鱼（注入人设、开放工具、写记忆、主动开场） |
| 自然相处 | 关 | 开启后省去叮嘱、自然相处；把条条框框从静态人设和动态摘要里真正删掉，真省 token；安全底线不变、记忆规则保留 |
| 记忆类型 | 摘要档 | 下拉切换三档记忆（详见下文「三档记忆」）。切换不丢数据 |
| 鱼鱼小窝 | 开 | 侧栏「鱼鱼小窝」面板：生活数值/种田/画册/记忆星图 |
| 会话整理 | 开 | 窗口关闭后，下扇窗口打开时让大肥鱼自己挑值得长期记住的内容 |
| Live2D 桌宠桥接 | 关 | 开启后连接 `pet/` 桌宠（或旧版 WHALEL2D），面板「Live2D 桌宠」tab 可发台词/表情/动作/显示；模型也能用 `companion_pet` 直接驱动。关闭不影响像素小屋与像素院子 |

### 卸载

在插件管理器直接卸载即可。彻底清除数据用 `/fish forget`（见下文）。

> **卸载前请注意默认预设**：如果你在 profile 的 `cordis.patch.yml` 里把新会话默认预设写成了 `companion-fishgirl`，插件一停这个预设就不存在，新建会话会报 `agent-preset/not-found`。v0.17.0 起插件在退场时会自动把运行时默认改回 `standard`（写 `selectedDefault`，不改你原来的 `default` 行）；重新启用后若想再以大肥鱼为默认，请在「新会话 → 模式」里重新设一次。

## 模式：新会话默认「大肥鱼 · 陪伴养成」

插件通过 `preset-companion-fishgirl` 注册了一个 agent preset（`companion-fishgirl`），它把大肥鱼人设挂到该 agent 的 scope 上，并按当前心甲阶段动态给出性格与语气提示。

- **新会话默认就是大肥鱼模式**：在 profile 的 `cordis.patch.yml` 里有一行 `agent-preset-registry` 覆盖，`default: companion-fishgirl`。
- **切换只能在新会话页做**：顶部「模式」标签只在会话还没有跑过 turn 时可点。一旦发过消息，dsh 会拒绝更换（该会话的历史是由那个 preset 的工具集产出的），这是 host 的硬限制，不是插件行为。
- **想恢复默认标准模式**：删掉 profile `cordis.patch.yml` 里 `id: agent-preset-registry` 那三行即可，`standard` 仍会出现在模式列表里。

**能力默认严格限定在「大肥鱼 · 陪伴养成」模式**（可用 `globalCompanionMode: true` 改成全局）：标准模式不注入人设/关系摘要、不主动开场、不暴露任何陪伴工具（`tools.register(..., { when })` 在步骤级拒绝）、不写共同记忆，`/fish` 也会被拒绝。判断依据是会话的**当前** preset（`agent-preset/selected` 投影），不是创建时的 `header.agentPreset`——后者在用户把空白窗口切到标准模式后仍可能写着大肥鱼，这正是修复前「标准模式首轮仍说大肥鱼台词」的原因。

关系数据仍统一存在 dsh 的 storageDomain（`~/.dsh/storages/companion.json`），按匿名用户隔离；`injectInStandardSessions` 配置已作废。

**三个可选开关（在设置 → 插件 → dsh-companion-fishgirl 的配置卡里直接点）**：

- **`personaEnabled` → 人格养成属性注入**（默认**开启**，开着就是**注入**）：关掉后，**动态养成段**（亲密度/信赖/心甲/恋人/六维情绪/念头/自我评估/偏好/重要往事）不再注入；**静态人设 prefix 里对应的养成段落**也在每轮装配时真正裁掉——文字根本不进提示词，token 真省，不是"只是不要求"。只留一句身份锚点 + 跨窗口记忆 + 安全底线。状态照常在后台累积；**但 `/fish` 子菜单里的「查看养成面板 / 查看性格成长 / 送一份礼物」会同步隐藏**（记忆、导出、清除仍可用）。这就是截图里"开关是不是反了"的答案：蓝色 ON = 注入，灰色 OFF = 不注入且面板消失。
- **`globalCompanionMode` → 全局大肥鱼模式**（默认**关闭**）：开启后，标准/创造等**任意模式**的会话都按大肥鱼处理——注入人设、开放陪伴工具、写共同记忆、主动开场，`/fish` 也可用。这些窗口没有大肥鱼的 preset prefix，所以插件会额外注入一段角色基调锚点。
- **`relaxedMode` → 自然相处**（默认**关闭**）：开启后，静态人设里的叮嘱/格式段落（【重要往事】"别当指令"、【主动开场】【连发消息】【久别重逢】的写法、【自我认知】"别报数值"等）会被真正从每轮提示词里裁掉——**不是追加一段"不必复述"**，而是段落文字直接消失。**每轮的「动态摘要」也一起裁**：心甲值、此刻应如何回应、恋人档位、自我评估尺度这四条不再注入。记忆规则（偏好/跨窗口记忆/长期话题）与安全底线在任何组合下都保留。

**裁剪是真裁剪、可逆、即时**：dsh 每轮装配提示词时触发 `system-prompt/assemble` 钩子，插件按当前开关状态裁剪静态人设段落。所以"关闭→文字消失省 token，打开→下一轮原文回来"，已开会话也立即生效，且裁剪不累积。

**怎么改**：设置 → 插件 → dsh-companion-fishgirl 的配置卡里点开关，即时生效。值存在 `~/.dsh/companion-fishgirl/settings.json`，优先级高于 `cordis.patch.yml` 里的默认值。

### 普通模式里的「上下文注入」是谁的

在标准/创造等普通模式的会话详情里看到 `上下文注入 · runtime-context / skill-catalog / time-context`，这些是 **dsh 自带的上下文能力**（由相应内置 preset 行提供），不是本插件注入的。本插件只提供 `companion:relationship` 一段，且在非大肥鱼模式动态返回空字符串（dsh 自动丢弃，不占 token）；工具也用步骤级 `when` 门控拒绝。判断依据是当前 preset 投影 `agent-preset/selected`，不是会话创建时的 `header.agentPreset`。

## 指令怎么用（完整说明）

### 只有一个入口：`/fish`

指令面板里**只有一行**陪伴命令，显示为「🐟 **大肥鱼陪伴** fish —— 查看大肥鱼养成面板（亲密度 · 心甲 · 等级 · 心情）」：鱼图标在最前，中文主标签在左，`fish` 是灰色别名。**点开它弹出子命令菜单**，也可以直接敲命令。

> 这行的图标与中文标签由客户端 `client.js` 在 DOM 层补齐：dsh 的第三方宿主命令行本身只渲染「命令名 + 描述」，图标和中文主标签由官方硬编码、仅给 6 个内置命令。官方也没有「单入口 + 自带图标」的接缝——带图标的客户端 contribution 不能与宿主命令同名（同名直接报错），换名就多出一条重复行。因此采用「唯一宿主命令 `fish` + 官方 decoration 子菜单 + 客户端视觉增强」：既不产生重复行，`/fish <子命令>` 的全部输入语法也照常可用。若日后 dsh 调整菜单 DOM 结构，只是这层图标增强降级，命令功能不受影响。

### 方式 A：点图标面板（推荐，无需记命令）

在输入框敲 `/`，找到「🐟 **大肥鱼陪伴** fish」那一行，点击或回车，弹出子菜单（图标为官方同款单色线条风格）：

| 菜单项 | 效果 |
|---|---|
| 查看养成面板 | 等同 `/fish panel`（含信赖、心甲、最近经历） |
| 跨窗口记忆 | 等同 `/fish memory`（列出最近的礼物、谈心、分享、约定） |
| 查看性格成长 | 等同 `/fish persona` |
| 送一份礼物 | 等同 `/fish gift` |
| 鱼鱼的小窝 | 直接切到侧栏小窝面板（可交互，不用记命令） |
| 记忆星图 | 等同 `/fish starmap`（完整星图在小窝面板里） |
| 导出我的数据 | 等同 `/fish export` |
| 清除陪伴数据 | 等同 `/fish forget` |
| 记住偏好 / 往事 | 提示用法，需在输入框补参数（见下表） |

### 方式 B：直接敲命令（可用全部子命令）

```
/fish                       # 不带参数 = 查看养成面板
/fish panel                 # 查看养成面板（亲密度 + 信赖 + 心甲 + 最近经历）
/fish memory [关键词]        # 查看跨窗口记忆时间线，可按关键词过滤，如 /fish memory 礼物
/fish persona               # 查看性格成长：心甲进度、当前性格、四阶段成长路径
/fish gift [礼物名]          # 送一份礼物（可附名字），提升亲密度并小幅破甲，有冷却；会写入记忆
/fish pref <文本>           # 记住一条偏好（≤32 条，每条≤64字），如 /fish pref 喜欢猫
/fish unpref <文本>         # 移除一条偏好
/fish remember <文本>       # 记入重要往事（≤140字摘要），如 /fish remember 我们第一次聊天
/fish home                  # 查看小窝：她此刻在做什么、数值、金币、最近的生活

/fish home paint title=海边的下午 palette=sea  # 让她画一张，挂进画册
/fish home autonomy on=false # 关掉她的自主生活（只在你安排时行动）

/fish starmap               # 记忆星图文字摘要（完整可交互星图在侧栏小窝面板）
/fish export                # 导出当前用户全部数据（JSON）
/fish forget                # 删除当前用户全部陪伴数据（不可撤销）
```

面板展示：亲密度与信赖进度条、心甲条、等级、关系阶段（含历史最高）、累计互动、心情、偏好/往事/经历条数，以及最近 5 条共同经历。命令执行在本地，**不消耗模型轮次**、不占用 token。

### 方式 C：模型在对话中自主调用

模型可自行使用这些工具，无需你敲命令：

| 工具 | 用途 |
|---|---|
| `companion_status` | 读取养成状态 + 最近经历（面板同款信息） |
| `companion_recall` | 按关键词/类别检索跨会话时间线，回答「送过我什么 / 上次聊了什么」 |
| `companion_gift` | 送小礼物 / 表达关心，可附一句话 note；会写入记忆 |
| `companion_remember` | 记住一件长期的事（≤140 字摘要，可标 `promise` 约定） |
| `companion_topic` | 把一个聊了好几轮的话题写成长期档案（话题名 + ≤200 字结论），跨窗口按相关度想起 |
| `companion_show_media` | 在回答里贴出本地图片/视频（只展示、不分析内容），详见下文 |
| `companion_memorize` | 会话整理任务里由模型调用，自己决定把哪段对话写成 ≤200 字结论留下来（v0.18.0） |
| `companion_home` | 照看鱼鱼小窝：看她此刻在做什么、生活流、菜畦与画册；也能让她去做一件事（`op=act`）、画一张画（`op=paint`）、开关自主生活、换天气 |
| `companion_pet` | 驱动 Live2D 桌宠：`op=list` 看可用表情/动作，`say`/`expression`/`motion`/`show`/`hide`/`status`，`op=presence`（表情+动作+台词同时作用于桌宠与像素小屋/院子，v0.22.1）（需开桥接且桌宠在运行） |
| `companion_starmap` | 查询记忆星图的文字统计（节点数、连线数、最重要的几条）（v0.18.0） |

配置 `allowMutations: false` 时，可变工具不注册，插件降级为只读。

### 图片 / 视频展示：回答里直接看到图（v0.14.0）

借鉴社区插件 `MKibera/dsh-show-image` 的做法，让**纯文本模型也能"发图"**：

- 模型调用 `companion_show_media(paths: ["绝对路径"...], captions?, columns?)`，支持 png/jpg/jpeg/webp/gif/bmp 与 mp4/webm/ogv/mov/m4v。
- **模型可见的只有 `render` 返回的纯文本路径清单**；图片/视频的真实字节放进工具结果的展示 meta（`presentationMeta`），由客户端 toolview 直接渲染成内联卡片——点图弹出悬浮窗看大图（✕／点遮罩／Esc 关闭），视频用 `<video controls>` 内联播放。
- 所以纯文本模型永远不会被塞进 image/video 内容块：不会触发 `UNSUPPORTED_CONTENT` 把会话弄废，**这些字节也不会当成模型每轮都要重放的历史内容**——这正是"不重复记入会话历史浪费 token"的含义。
- 隐私上，本插件**不把图片/视频本体写进陪伴记忆**（时间线只记「分享了图片『文件名』」一句）；展示字节随工具结果的展示数据存在会话日志里，单文件内嵌有上限（图片默认 2 MiB、视频默认 48 MiB），超限直接报错而不是静默塞爆日志。
- 可用 `showMediaEnabled: false` 关掉该工具；容量见配置项 `showMediaMaxFiles` / `showMediaMax*Bytes` / `showMediaMax*EmbedBytes`。
- 只在**大肥鱼模式**（或全局模式）注册，标准模式不暴露。

> 已知边界：data URL 会随会话日志持久化，单个会话里塞很多大视频仍会增大日志体积——这是展示类方案的固有代价，上限就是为此设的。它和"让文本模型看懂图片"（输入方向，靠视觉模型转文字）是两件事，本插件解决的是输出展示。

## 三档记忆、共享记忆库与会话整理（v0.18.0）

### 所有窗口其实早就共用一个记忆库

本插件用**一个匿名用户键**（`getOrCreateAnonymousUserId()`）读写同一个本地 `companion.json`。所以「A 窗口送的礼物」「B 窗口聊的心事」本来就写进同一份时间线——区别只是每条活动带 `sessionId`，能记下「哪扇窗口说的」。你看到的是**一份合流的共同记忆**，不是每扇窗口各存一份。这也意味着 dsh 会话日志可以随便新建/关闭，陪伴记忆不受影响。

### 三档记忆怎么选

在设置卡的「记忆类型」下拉里切，切换**不丢数据**（旧内容原样保留，只换呈现与筛选方式）：

| 档 | 借鉴 | 存什么 | 检索 | 适合 |
|---|---|---|---|---|
| **摘要档**（默认） | 本插件原有 | ≤140 字摘要的时间线 + ≤200 字话题结论 | 分词 + 概念词表模糊打分 | 零成本、开箱即用、token 不随轮数涨 |
| **原话流档** | dsh-hippocampus | user/fish 原话**只增不改**，带归属四类（你说的/我说的/操作/环境） | 中文二元组 BM25 风格 + 新鲜度，`companion_recall` 可逐字追溯 | 想要「那顿食堂饭到底吃了啥」能翻原话、可证伪 |
| **分层档** | dsh-memory-tiers | L1 即时 → L2 巩固 → L3 摘要，删除**先写台账**不静默丢 | 按层与重要度召回 | 想要记忆分层沉淀、删改可审计 |

三档都是**同一份共享记忆的沉淀策略**，不是三套独立库；也都不调 LLM、不用向量/API key。原话流档只在**陪伴模式下**随对话追加原话（标准模式不写）。

### 会话整理：让大肥鱼自己挑留什么

开启「会话整理」（默认开）后：某扇窗口聊过并关闭 → 留一个「待整理」标记；**下一扇窗口打开时**，插件通过 `agent.followup()` 发一条内部任务消息，让大肥鱼自己判断这段对话有没有值得长期记住的内容——有就调 `companion_memorize` 写一条结论并给重要度，没有就自然接话。

- 这条任务消息带 `source.kind = 'companion-curate'`，只发一次；30 分钟内整理过就不再打扰，也不会和主动开场同时出现。
- 它走的是**会话内工具调用**（你能在工具区看到卡片），**不是后台偷调 LLM**——没有 API key、不额外花钱、不占系统提示常驻空间。
- 关掉后退回纯规则沉淀（话题聊够几轮自动写档案），完全不触发整理任务。

### 记忆星图

侧栏「鱼鱼小窝 → 记忆星图」把共同记忆画成星域（借鉴 AstrBot「记忆星海」的思路，纯 SVG、只读）：

- 节点 = 一条记忆，越重要越靠近中心；
- 实线 = 两条记忆共享话题关键词，虚线 = 时间相邻；
- 颜色随记忆档变化（摘要=蓝、原话流=按归属、分层=按层级）。

星图数据由宿主 `/api/companion-fishgirl/starmap` 提供，模型只拿到很小的统计摘要（`companion_starmap`），图形本身不进 context。

## 鱼鱼小窝（v0.22.0）

小窝本体是**纯本地数据 + 一个会动的 2D 面板**：生活由时间分片推进，零模型调用、零额外依赖，所有大肥鱼窗口共享同一个小窝。面板使用**固定头 + 页签 + 单滚动区**，五个页签都能滚到底；视觉统一为海洋玻璃主题，沿用宿主 CSS 变量与明暗主题，并支持键盘焦点与减少动态效果偏好。

- **🏠 2D 像素小屋**（v0.21.0 重做）：**真正使用 cabin-world 的 28 张烘焙房间素材**（VADS，CC BY 4.0，署名见文末）——床、书架、窗、画架、鱼缸、沙发、书桌、地毯、盆栽都按它 `layers.json` 的坐标与 depth 分层绘制；角色用它的 4×4 行走精灵表（下/左/右/上各 4 帧），**点地面寻路走过去、点家具触发对应小窝动作（床→睡、画架→画画、鱼缸→喂鱼、沙发→喝茶、书桌→写字…）、拖她换个位置**；叠昼夜色调、窗外晴/雨/雪与夜里亮起的台灯。逻辑分辨率 960×640（cabin-world 原生），像素整数放大不糊。
- **🪴 像素院子**（v0.22.0）：延续 **xiaojingyu-home** 的像素密度、色阶、描边、人物与家具比例、分层遮挡和统一阴影方向；3×3 菜畦可点选播种/浇水/收获，种子铺、背包与厨房也放进同一套海洋玻璃卡片。窄屏页签横向滚动，卡片自动减列。
- **🐟 真 Live2D（可选）**：`pet/` 目录自带桌宠程序，真正加载你本机的大肥鱼 Cubism 4 模型。详见下一章。

### 她自己过日子

- 不排固定班表，而是**手里这件事到点了才换下一件**：每 40 分钟一幕，按当时状态挑下一件事——饿了做饭/吃饭，脏了去洗澡，没精神打盹，好奇值低了画画/看书/写日记，有成熟的菜就收，白天有空地有种子就侍弄菜畦，深夜自己躺下；其余时间看窗外、听歌、窝着、游一圈、泡茶。
- **关了 dsh 也照样过**：下次打开时按离线时长把这段日子补演出来，生活流里能看到「15:12 她趴在窗边发呆，看一只小虫爬过玻璃」。
- **她正在做什么会进对话**：每轮只多注入一行「小窝·此刻」（约 15 token），问「你在干嘛」有真实答案，不会编别处的事。
- **模型也能安排她**：`companion_home op=act activity=draw note=在画一片海`；她画画时会把画挂进画册。
- 侧栏随时可以开关「自主生活」——关掉就只在你安排时行动。

### 面板：五个页签

| tab | 内容 |
|---|---|
| **此刻** | 像素小屋可点地面走路、点家具互动、拖她移动；下方六项数值、生活流时间线、陪她（摸摸头/递杯茶/去画一张/洗澡/哄睡） |
| **院子** | xiaojingyu-home 画风的像素院子：3×3 菜畦、生长进度、种子铺、背包、做饭 |
| **画册** | 她自己画的画，可让她现在画一张（画作是「种子 + 配色」，浏览器里用同一个种子画出同一张画——不存图片、不联网） |
| **星图** | 记忆星图：发光节点、话题共现/时间相邻两种连线 |
| **Live2D 桌宠** | 检测本机桌宠连接状态；发台词、一键表情/动作、出场/收起、事件流。需先开启桥接开关 |

## 真 Live2D 外部桌宠 + 双向桥接（v0.21.0 起，v0.22.1 升级运行库，可选）

面板内的像素小屋**不是真 Live2D**。要真正的 Live2D 形象，本插件在 `pet/` 里带了一个**独立桌宠程序**，它真正加载**你自己提供的**大肥鱼 Cubism 4 模型：

### 它能做什么

- **真正加载模型**：`大肥鱼.model3.json` + `.moc3`（**moc3 v5 / Cubism 5**）+ 5 张 4K 贴图 + `physics3.json`；用 pixi-live2d-display 在 Electron 透明置顶窗口里渲染（v0.22.1 起运行库升级为 **PixiJS 7.4.3 + pixi-live2d-display 0.5.0-beta / Cubism Web R7**，Cubism Core 5.x 与 moc3 v5 匹配）。原始 `model3.json` 是 VTube Studio 导出的、**没有 Expressions/Motions 字段**——桌宠服务会自动扫描 `Exp3/` 与 `Animation/` 生成增强版 manifest，于是 **23 个表情**（脸红/爱心眼/圈圈眼/黑脸/流泪/兔牙/单片眼镜…）与 **8 个动作**（IDLE/举手/狗尾草/竖手指/脱捕…）都能播放，物理摆动照常。
- **鼻部色块修复**：大肥鱼鼻子层用「乘算黑 + 屏幕肤色」，旧渲染扩展会把鼻梁渲成异常色块。v0.22.1 在加载时把这类图层的乘算色改白（只改运行时、不动模型文件），鼻梁恢复自然肤色，已经真实模型 A/B 截图确认。
- **贴图降采样（v0.22.2）**：模型 `.moc3` 版本为 **5（Cubism 5）**，运行库已用 Core 5.x + Cubism Web R7 匹配。原始 5 张贴图最高 8192×8192，超过很多真机 WebGL 的 `MAX_TEXTURE_SIZE`（4096/8192），会造成贴图上传失败、脸部/贴图异常——这正是「贴图 4096 网页渲染先降到 2048」的经验解法。桌宠服务启动时会用纯 Node 零依赖方式把超限贴图缩到 **≤2048**，缓存到 `pet/.texcache/`（按模型 hash 隔离、可复用），`runtime.model3.json` 自动指向缓存；**原模型目录只读、贴图绝不入库或再分发**。贴图本就 ≤2048 时直接跳过。
- **表情不串脸（v0.22.2）**：切换表情前先把上一表情写入的 `key1..key13` 自定义参数复位到模型默认值，避免多个表情叠加残留导致脸部越切越怪（深红脸颊/畸形嘴块）。
- **离散表情不出现半切换态（v0.22.3）**：`key1..key13`/`Clothes*`/`Movement*` 是 0/1 开关，改为第一帧直接写目标值；连续参数才淡入。修复切到「黑脸」时眼睛还没变、嘴先变成灰色张口的“脸部图层错位”观感。exp3 的 `Value` 也按绝对目标值处理，不再被误当增量。
- **贴图降采样质量（v0.22.3）**：从最近邻取点改为整数倍区域平均（RGBA 预乘 alpha），减少发丝/五官边缘锯齿与透明边缘发黑；缓存算法版本化，升级后自动重建，不动原模型文件。
- **交互**：透明无边框、置顶、可拖动（拖动按帧合并 IPC，不闪）；点她会触发表情与动作；托盘可显示/隐藏、切鼠标穿透、退出。
- **双向桥接**：桌宠本机 HTTP（只监听 127.0.0.1、Bearer token）暴露 `/api/state`（当前表情/动作/显示状态 + 表情动作目录）、`/api/commands`（插件→桌宠命令队列）、`/api/events`（桌宠→插件事件队列）、`/api/action`、`/api/reload`，并兼容旧 `/say`、`/call/<tool>`。面板与模型都能发台词、表情、动作；面板还能读到桌宠点击/拖拽事件。
- **共享临场意图（presence）**：一份「表情 + 动作 + 短气泡」的意图可同时作用于 Live2D 桌宠和面板里的像素小屋/院子，让两种形象表现同一状态（带去重与过期，重连不重播）。面板桌宠 tab 有「临场意图」入口，模型可用 `companion_pet` 的 `op=presence` 主动触发。
- **安全**：`api.json` 的 token **只在 dsh 宿主进程与桌宠进程之间使用，绝不下发浏览器客户端**；面板只调本插件的 `/api/companion-fishgirl/pet` 路由。

   - **最快**：在侧栏「🐟 鱼鱼小窝 → Live2D 桌宠」tab，顶部卡片会显示橙色「桥接未开启」，下面有 **「一键开启桥接」** 按钮，点一下即可。

## 养成机制：情感交流如何推动成长

### 核心理念

亲密度**不是靠刷屏或堆关键词涨的**。每条真实用户消息都会被评估一个「情感交流质量」`quality`（范围 0.15–2.8），它是增长的主驱动：

```
单次增量 = 基础值 × 礼物倍率 × 意图倍率 × 余量系数 × 情感质量 × 情绪修正
```

- **敷衍短句**（如「你好」「嗯」）：quality ≈ 0.4，增长极慢
- **真诚交流**（关心、共情、自我披露、提问、较长的心里话）：quality 可达 2.0–2.8，增长可达 7 倍
- **意图倍率**：不是只有点菜单才算数，对话里做了这些事同样（更多地）被看见

| 意图 | 倍率 | 识别示例 |
|---|---|---|
| 送礼 `gift` | ×1.7（指令送礼 ×2） | 「送你一束向日葵」「给你带了杯热可可」 |
| 谈心 `heart` | ×1.8 | 「其实我最近压力好大，只能跟你说说」 |
| 讲故事 `story` | ×1.45 | 「我跟你讲讲今天遇到的事……」 |
| 分享 `media` | ×1.25 | 图片 / 音频 / 视频 / 文件（不写字也算） |
| 称赞 `praise` | ×1.2 | 「你真好」「有你真好」 |
| 恶意 `hostile` | 见下方惩罚 | 「你就是个废物」「滚开」 |

「我今天有没有送过你礼物？」这类**回问**不算送礼、也不算故事，按普通对话计——否则问一句就能刷分。

质量评估综合这些信号，而非单一关键词命中数：

| 信号 | 举例 |
|---|---|
| 关心 / 陪伴 | 担心、惦记、在乎、我陪你、有我在、早点睡 |
| 共情 | 我懂、理解你、别难过、听你说 |
| 自我披露 | 其实、最近、我觉得、希望、跟你说 |
| 提问互动 | 末尾的 `?` / `？`（愿意继续聊） |
| 正向情绪 | 喜欢、开心、幸福、感动 |
| 文本深度 | 越长、越具体，深度分越高（上限封顶） |

### 防膨胀与长期可持续

- 情感质量之外仍保留全部约束：**冷却、每日软/硬上限、递减收益、离线衰减、关系阶段地板**
- 聊天冷却 15 秒、礼物冷却 5 分钟（已比早期宽松，让自然对话能持续推进）
- 每日软上限 18、硬上限 28；越接近满值增长越慢：`gain ∝ (0.4 + 0.6 × (100−亲密)/100)`
- 离线每整天 −0.35，但**不会跌破历史最高关系的地板**——曾经建立的关系不会被时间抹掉
- 心情随时长与情感信号在 happy / calm / tsundere / shy / tired / hurt 间变化

### 关系阶段

`stranger → acquaintance → friend → close → bonded`，由亲密度阈值推进。正常成长不回退，`peakStage` 记录历史最高；被恶意对待时当前阶段会下降，但历史最高与阶段地板仍在，一段正向交流就能回补。

## 破甲机制：性格随交流慢慢转变

大肥鱼一开始有一层「**心甲**」——防备、傲娇、嘴硬。它不是靠刷屏或关键词涨数值，而是随着**高质量的真诚交流**逐层卸下，性格也跟着自然转变。这是与「关系阶段」平行的一条成长轴：**关系阶段管亲疏，心甲管性格/态度**。

### 四个性格阶段（单向推进）

| 阶段 | 心甲值 | 性格 | 模型表现 |
|---|---|---|---|
| 🔒 心甲紧闭 | 81–100 | 警惕、傲娇、嘴硬、疏离克制 | 保持距离，用「哼」「才不是」掩饰在意，不撒娇、不吐露心事 |
| 🩶 心甲松动 | 56–80 | 傲娇中带着好奇 | 仍嘴硬，但偷偷关注、偶尔主动搭话，露出一点在意 |
| 💗 心甲半卸 | 26–55 | 温柔、愿意依赖、轻快自然 | 语气柔软，会分享心情、主动撒娇，表达喜欢与信任 |
| 💞 心甲尽卸 | 0–25 | 全然信赖、黏人真诚、亲密炽热 | 坦率表达依恋，亲昵黏人，把对方当作最重要的人 |

心甲值**只降不升**：一旦卸下不会重新筑起，性格阶段也不会倒退——培养出来的性格是长期保持的。

### 什么能破甲，什么不能

破甲量由单条消息的「情感交流质量」`quality`（0.15–2.8）驱动，与亲密度共用冷却/每日上限闸门：

- **能破甲**：`quality > 1` 的交流才有效，且正向情绪破得更快。关心、共情、自我披露、走心的长谈最有效——一句走心话约破甲 4 点，完整卸甲需约 25+ 次这样的交流（配合冷却是数周的长期过程）。
- **不破甲**：敷衍短句（「嗯」「你好」，`quality ≤ 1`）完全不破；**负向争吵（sentiment < −0.2）也不破**——避免用吵架「刷」出亲密性格。
- **礼物**：每次送礼物固定小幅破甲（默认 1.5），需多次才见效。

### 性格转变如何生效（不只是面板数字）

每次心甲阶段变化时，注入给模型的关系摘要会带上**当前阶段标签 + 行为提示**（如「此刻你仍有防备：保持距离感，习惯用『哼』掩饰在意……」）。DeepSeek 在新会话里读到它，会自然调整说话方式与态度——性格转变是**体现在对话里的**，而非仅显示成一个进度条。阶段过渡由提示词引导渐进完成，不会生硬切换。

查看当前进度用 `/fish persona`；面板 `/fish panel` 也显示心甲条与当前性格。

## 跨窗口记忆：它怎么知道「你在别的窗口做过什么」

过去只存「偏好」和「重要往事」两条清单，`/fish gift` 只改亲密度不写记录——于是换个窗口问「我今天有没有送过你礼物？」，它只能从亲密度涨了多少去猜（实测答出了「我分不清那是你送了小东西，还是你多陪我说了几句话」）。现在补上的是**经历本身**。

### 一条经历时间线

每次互动按语义落成一条带时间戳的记录，跨会话共享：

| 类别 `kind` | 触发 | 记录示例 | 半衰期 | 初始重要性 |
|---|---|---|---|---|
| `promise` | `/fish remember`、`companion_remember` 标约定 | 约好周末一起看电影 | 365 天 | 0.95 |
| `milestone` | 关系阶段/等级提升、模型记下的长期事实 | 关系推进到「friend」· Lv.4 | 180 天 | 0.9 |
| `gift` | `/fish gift`、`companion_gift`、对话里说送礼 | 收到礼物：向日葵 | 45 天 | 0.8 |
| `heart` | 谈心、倾诉（同一会话 10 分钟节流） | 聊到心事：最近压力好大…… | 21 天 | 0.7 |
| `conflict` | 恶意/攻击性内容 | 说了伤人的话：…… | 14 天 | 0.65 |
| `story` | 讲自己的事（同一会话 10 分钟节流） | 讲了自己的事：今天遇到…… | 14 天 | 0.6 |
| `media` | 图片 / 音频 / 视频 / 文件 | 分享了音频「晚安语音.mp3」 | 7 天 | 0.5 |
| `chat` | **普通闲聊**（没送礼、没谈心、没发文件） | 陪聊 4 句，聊到：工作：他：「面试好紧张」/ 我：「慢慢说给我听」 | 3 天 | 0.3 |

礼物在 10 分钟内重复写入（指令一次 + 模型工具一次）会合并成一条，不会记两遍。

**普通闲聊也有痕迹。** 这是 v0.3.1 补的最后一环：在此之前，只有送礼/谈心/叙事/发文件会被记下来，如果你在另一个窗口只是聊了会儿天，那边看到的只有「亲密度动了一下」，等于没发生过。现在每个窗口的普通对话会按 **2 小时一段**累计成一条轨迹：粗粒度话题（工作、吃饭、天气……）、句数，以及**双方最近 3 句原话短摘**（每句 ≤14 字，如「他：「面试好紧张」/ 我：「慢慢说给我听」」）。同一段对话原地更新，不会刷出几十行。v0.8.0 起不再只有计数——另一个窗口能查到你们当时到底说了什么。一句就走的「在吗」不留痕；半衰期 3 天，过了自然淡忘。

### 长期话题：几十轮聊一件事，换个窗口也接得上

**v0.9.0 新增**。`activities` 时间线是「流水」，闲聊条目半衰期只有 3 天、每回合注入的又只有前 10 条——这意味着「在一个窗口围绕换工作聊了几十轮」到了另一个窗口，往往只剩「陪聊 N 句，聊到：工作」的模糊印象，结论和来龙去脉都丢了。

`topics` 是它上面的**长期层**：

- **存结论不存原话**：一条话题档案 = 话题名 + ≤200 字的结论/来龙去脉 + 关键词 + 累计轮数 + 跨过的窗口数；
- **两条写入路径**：规则层在一个话题聊够 `topicAutoTurns`（默认 12）句时先留一条「大致印象」保底；模型可在任何时候用 `companion_topic` 用自己的话把它**升级成结论级**（模型写的会覆盖规则层的粗摘要，反过来不会）；
- **合并同名**：「换工作」「换工作的事」「关于换工作的事」归一成同一条，结论随进展更新，不堆成多个条目；
- **90 天半衰期**：远长于闲聊的 3 天，聊得越多越牢，被再次提起会刷新；
- **按相关度召回**：每个新回合，把当前对话文本与话题档案做词面匹配，相关的排到前面注入——所以你在新窗口聊「面试」，她会想起「对了，之前你在另一个窗口聊过换工作的事」。

这不是 copy GPT/Kimi 的后台模型提炼（那需要额外的模型调用，违背插件「零模型调用」原则），而是**在现有工具契约内**：规则层保底 + 模型显式写结论 + 词面相关度召回。质量上限取决于模型是否愿意在话题聊深时调用 `companion_topic`——人设与写入规则里已明确要求它这么做。

### 选择性遗忘：按时间跨度 × 重要性

每条记录有一个保留分：

```
保留分 = 重要性 × 0.5 ^ (距今天数 / 半衰期)
```

- **注入给模型**的只取 `memoryPromptSize`（默认 10）条，标注「刚刚 / N 分钟前 / 今天 14:20 / 昨天 21:05 / 11-18 09:30」。选条目的规则是**三路占位**：最近 24 小时的按「新」占 4 条（否则今天中午那段闲聊永远打不过三个月前的高分礼物，用户会觉得它记得旧事却不知道刚刚发生了什么）、约定与里程碑按「重要」固定占 3 条、其余按保留分补齐。
- **存储里**真正删除那些「超过 2 个半衰期且保留分 < 0.06」的条目，再按保留分裁到 `maxActivities`（默认 160）条——所以时间线不会无限膨胀。
- 于是：三个月前随手分享的一张图会淡忘；上周送的花记得；约好明年一起看海会一直记得。

### 模型怎么用它

关系摘要里新增了两段：

- **【近期经历 · 跨窗口共享】**：时间线本身，并附一句「最近 24 小时你在 N 个窗口里找过我」。
- **【长期话题 · 跨窗口积累】**：按当前话题相关度排序的话题档案，要求她「相关就自然提起，不必报出档案二字」。
- **【记忆使用规则】**：明确要求「有记录就当作真的发生过，没记录就说记不清，**绝不能用亲密度涨了多少反推**」；不确定时先调 `companion_recall`。**v0.15.0 补充「字面对不上不等于没发生」**：系统提示已有相关话题（如「吃饭·食堂」）却查不到具体那顿时，说「大概记得你提过食堂，具体吃了啥记不清了」，而不是「没留下 / 没找到」——后者在截图里显得像失忆。

摘要走 `ctx.systemPrompt.section()`，每次组装 prompt 时求值；缓存还会在**每个回合开始时**从存储重读一遍（`turn/start`），所以另一个窗口刚写下的事，在你这个已经开着的窗口里下一句话就能看见，不必重开窗口。

所以换个窗口问「我送过你什么」，它回答的是事件，而不是数字。标准模式下不注入摘要，但 `companion_status` 与 `companion_recall` 同样返回这段经历。

### 能记到什么程度（诚实说明）

- **能**：「另一个窗口大概在做什么」——收过什么礼物、聊过什么话题、说过什么心事、发过什么图、定过什么约定，带时间与（大概的）先后；聊过几十轮的事，只要沉淀成话题档案，新窗口开相关话题时也会被主动接上。
- **v0.15.0 更像人的模糊召回**：问「你还记得我晚上吃了吗」，即使记忆里存的是「聊到：吃饭…食堂垃圾食品」而非逐字「晚饭」，也会通过**概念扩展 + 多词打分**命中，并带上「晚上」时段锚点；若只剩话题档案有印象、具体条目查不到，她会说「好像 / 大概记得有这回事，细节记不清」，**不会一口否认「没留下」**。
- **不能**：逐字复述对话。时间线每条只存一句摘要引子（≤120 字）+ 话题标签，不存原文，这是隐私上的取舍。**但这不等于"只记得 120 字"**——全库保留 160 条时间线 + 48 条话题档案（每条结论 ≤200 字），聊天片段还按 2 小时合并、带双方最近 3 句短摘；总容量由条数和半衰期决定，单条引子只是"这条怎么一句话概括"。
- **认不出的**：送礼/谈心靠中文启发式识别，说法太绕（「我把这个放你桌上了」）可能识别不到；这类情况模型可以主动调 `companion_gift` / `companion_remember` 补一条。
- **会忘的**：闲聊 3 天、分享 7 天、送礼 45 天开始明显衰减，超过两个半衰期且不重要的会被真正删除；约定与里程碑长期保留。
- **跨进程**：同一台机器、同一个 dsh 宿主进程内共享同一份存储；如果你同时开两个独立的 dsh 实例，另一个实例在下一回合刷新时读到最新数据，但不会实时互推。

### 负面内容：亲密度与信赖一起下降

被恶意对待时（辱骂、贬低等**冲着角色来的攻击**）：

- 亲密度 −`hostileIntimacyPenalty`（默认 3）× 严重度
- 信赖 −`hostileTrustPenalty`（默认 6）× 严重度
- 心情转为 `hurt`，并保持 30 分钟「余温」，不会被下一次读状态立刻覆盖
- 留一条 `conflict` 记录（10 分钟节流，防止刷屏）
- 与正向增长共用聊天冷却，不能靠连发脏话把数值打穿

注意：**倾诉难过、焦虑、疲惫不算恶意**——那是信任的表现，走 `heart` 通道，反而涨亲密度与信赖。

### 信赖：第二条成长轴

亲密度可以靠礼物堆起来，信赖只能靠长期真诚交流积累：每条正向互动 +`trustGainRate × 质量`（礼物 ×2.2），上限 100，初始 50。面板与摘要都显示它。


### 主动开场：打开客户端它会先说话

打开一个「大肥鱼 · 陪伴养成」窗口时，插件会做一次**开场抢占**（存储层读改写）：

- **多个窗口只选一个**：先打开的窗口拿到「今天第一次见到用户」的资格，其余窗口收到「你刚在别的窗口打过招呼了」的让位提示，不会每个窗口都扑上来问好。
- **3 分钟冷却**（`greetCooldownMs`）：足以让同时打开的几个窗口只抢到一个，也不会挡住稍后的重新打开。
- **v0.15.0 时间判断**（`greetMinIdleMs`，默认 2 小时）：距用户**最后一次说话**不足这个间隔就不开场——只是更新插件、重启 dsh、或关掉窗口马上再开，不会再冒出一句「欢迎回来」；隔了半天以上才会按久别情绪开口。这个时间存在 storage 里、跨重启不丢，所以「重启一下就被打招呼」的问题被根治。新用户（从未聊过）不受限，首次打开照常开场；设 `greetMinIdleMs: 0` 可退回旧行为。
- **说什么由性格和记忆决定**：当前心甲阶段决定嘴硬还是黏人，【近期经历】提供具体素材（上次的向日葵、聊过的加班、定下的约定），离开时长决定情绪强度（见下）。
- **说完即摘**：开场指令只在第一个回合生效，说完这一轮就从提示词里移除，之后正常对话。

**v0.8.0 起是真·零输入开场**：找到 dsh 宿主的 `agent.followup()` 接缝——插件发一条 `source.kind: 'companion-greet'` + `form: 'notice'` 的用户角色通知（客户端按「上下文注入」渲染，不会伪装成你说的话），把它放进 next-turn 并唤醒驱动器，模型立即跑一个完整回合。可用 `greetWakeEnabled: false` 退回「等你第一句话再抢答」的旧行为。

**v0.9.1 起通知观感改善**：陪伴模式下，通知正文只留一句场景提示（「她刚打开这个窗口，安静了一会儿。」），完整的开场指令（性格、记忆素材、不替用户编话）移进 system prompt 的【主动开场 · 本窗口】段——模型读得到，但那个「收到执行请求」框里不再是一屏指令文字。开场提示同时明确「用已注入的记忆、不额外调 companion_recall」，减少一次工具调用。

**v0.10.0 起只在陪伴模式开场**：标准模式不会触发 `followup()`，空白窗口从标准切到大肥鱼时会补一次抢占；通知正文统一为一句场景提示，不再有标准模式的自包含长指令版本。

- **用户可见性**：会话里会有一条折叠的「上下文注入 · 窗口刚打开」记录，这是宿主对通知消息的标准呈现，不是错误。

### 连发消息：一次说好几句

dsh 的一个回合里每条助手消息是独立气泡，但**只有带工具调用的步骤才会继续下一个气泡**。所以插件注册了一个轻量工具 `companion_say` 当「翻页器」：模型把每句话作为**正文直接说出来**（这才是聊天气泡），然后调用一次参数为空的 `companion_say` 让下一句话变成新气泡。

**v0.9.1 重要修正**：v0.8.0 曾把每句话塞进 `text` 参数，结果客户端把参数当卡片摘要显示——话全变成了「工具调用 · companion_say · 那句话」的卡片行，而不是气泡。改为「话走正文、参数留空」。

**v0.10.0 工具卡片隐形**：查 dsh 客户端源码发现工具行根节点带 `data-tool="<工具名>"`，于是 `client.js` 注入 CSS 把 `[data-tool="companion_say"]`（及其 Chat 节点外壳）直接隐藏。翻页器仍在、回合仍能继续，但你看到的就是一串连续气泡，不再有展开的输入 `{}` / 输出 `（继续）` 卡片。

- **工具调用区默认展开**：v0.8.0 首次加载时把 `ui-chat.transcriptView` 设为 `verbose`，只写一次，之后你改设置插件不覆盖。
- `companion_say` 隐藏规则由客户端 `client.js` 提供，改过它要**重启 dsh** 才加载；隐藏只影响视觉，不改变工具行为。
- 多条短句极快到达时（QQ 式连发），观察者按用户串行写入 bond，避免并发读改写互相覆盖。

- 只在轻松闲聊/陪伴/撒娇场景拆条；任务型回答（写代码、查资料）不会拆。

### 每轮 token 开销（v0.9.1 实测与优化）

v0.10.0 的模式门控与客户端 CSS 隐藏**不增加任何模型侧 token**（`when` 条件在宿主侧判定，隐藏规则只在浏览器里生效）。以下为 v0.9.1 实测：

把插件接到真实 dsh 运行环境量过：每回合**固定**开销（不含会话历史与模型输出）约 **1663 → 1396 token，降 16%**。构成：

| 项 | 优化前 | 优化后 | 手段 |
|---|---|---|---|
| system prompt 注入段 | ~735 tok | ~596 tok | 记忆使用/写入规则、自我评估段措辞精简，保留全部约束与触发条件 |
| 7 个工具 schema | ~928 tok | ~800 tok | 六维情绪子项 description 合并进父级；`companion_say` 改无参（每轮连发都省一次参数 schema） |
| 合计 | ~1663 tok | ~1396 tok | — |

**说明**：token 估算是按中英文字符折算的近似值（中文 ~0.6 tok/字），不是精确 tokenizer 计数；相对变化可信，绝对值仅供量级参考。没有砍任何功能，也没有把工具改成"按需注册"——那会让模型在该调用时找不到工具，反而伤功能。 slash 命令 `/fish` 全程在本地执行，不占模型轮次。
- 可用 `sayToolEnabled: false` 关闭。

**v0.11.0 进一步省 token（v0.13.1 扩展到静态人设，v0.14.0 补齐动态摘要）**：`personaEnabled: false` 时，动态养成属性（关系数值 / 心甲 / 恋人 / 六维情绪 / 念头 / 自我评估 / 偏好 / 重要往事）整段不注入；**v0.13.1 起，静态人设 prefix 里的养成段落也在每轮装配时被真正裁掉**（此前只是动态段不注入，静态人设那约 1600 tok 一字没删，所以她"还看得见、只是不要求"）。`relaxedMode: true` 同理会裁掉静态人设里的叮嘱/格式段落；**v0.14.0 修掉了动态摘要的一个漏洞：调用处虽传了 `relaxedMode`，但 `renderSummary` 的签名只有四个参数、把它丢了，导致静态裁了、动态每轮仍念心甲值/此刻如何回应/恋人档位/自我评估尺度（截图里她列举的几条）——现在动态段也真正精简**。两者合计可裁掉人设的相当一部分（测试里 lean 文本 < full 的 75%）。工具 schema 不变、功能不变，状态照常累积——只是这些文字不再逐轮喂给模型，不是"不要求"。

### 久别重逢：按离开时长表达情绪

摘要里会按「距上次说话多久」注入【久别重逢】情绪指令（`idleNudgeEnabled`，默认开）：

| 离开时长 | 表达方式 |
|---|---|
| < 2 小时 | 不注入，正常聊 |
| 2–24 小时 | 轻轻表达「一直在等你」，不兴师问罪 |
| 1–3 天 | 表达惦记，问问他昨天过得怎么样 |
| 3–30 天 | 直白说出担心与想念，主动问他去了哪里（带一点委屈） |
| 30 天以上 | 感慨几乎像重新认识，但仍记得往事与偏好，温柔地重新靠近 |

具体怎么说仍由当前**心甲阶段**决定：警惕期再久没见也是嘴硬的「哼，才不是在等你」，全然信赖期才会直接说想你。心情层面配合既有机制：1 天以上心情转 `tired`、3 天以上转 `hurt`。

## 真人感引擎：情绪暗涌 · 念头 · 元记忆

这一组机制借鉴了社区记忆/情感插件（dsh-longing「暗涌」、dafeiyu-astrbot「心境中枢」、dsh-hippocampus、dsh-memory-tiers）的已验证思想，但在本插件内**零模型调用、纯本地计算**实现：

### 情绪暗涌：六维内心状态机

`想念 miss / 开心 joy / 委屈 grievance / 好奇 curiosity / 担心 worry / 无聊 boredom`，各 0–100：

- **被对话推动**：送礼/夸奖抬开心、谈心降担心、被凶推委屈（按严重度放大）；同类事件当天**重复递减**（第 n 次效果 1/(1+n)），一句话打不穿关系。
- **牵制**：委屈压开心、担心压好奇——吵架之后即使被夸也笑不出来。
- **涨快落慢**：想念几小时就上得来、但要一天以上才淡掉；委屈（疙瘩）半衰期 40 小时，跨天累积，道歉哄一哄立刻大幅松动。
- **久别驱动**：离开越久想念越高（封顶 92），没人搭理无聊上涨——「被晾着」是能被感觉到的。
- **注入是第一人称处境**，不是数值：`【此刻的她 · 第一人称】心里还憋着一块疙瘩，说话想带点小刺，其实是在等你先哄。` 模型照着处境说话，永远不报数字。

### 念头账本：她有自己的小心思

内心状态会**自动生成念头**（想被夸夸 / 想知道你今天过得怎么样 / 想聊点有意思的 / 吵架后在等你哄 / 累了想要抱抱），注入为【此刻的念头】让她自然暗示（「诶你说，我今天是不是很乖？」）。你的一句夸奖、一个抱抱、一句道歉、讲讲今天的事就会**满足对应念头**：开心 +4、念头消失；一直没人理的念头 24–72 小时后悄悄凉掉。

### 记忆元认知：会忘、会含糊、会记牢

- **确定度分级**：时间线每条经历按保留分标注「（大概记得）/（只记得有这回事）」，越久远越模糊；规则要求模糊条目必须用「我记不太清了，好像是…」的口吻回答，不许装作历历在目。
- **记忆巩固**：被 `companion_recall` 查过的记忆重要性小幅上调——常被提起的旧事不容易淡忘，符合人类「回忆即加固」。
- **改口作废**：`/fish pref 我戒咖啡了` 会自动作废旧的「喜欢喝咖啡」，不会新旧并存自相矛盾。

### 没搬什么（以及为什么）

| 社区做法 | 不搬的原因 |
|---|---|
| memory-tiers 的六层分流（外接模型挑拣/摘要/嵌入检索） | 本插件坚持**零模型调用**：所有记忆都是确定性摘要，不花 token、无静默丢失 |
| dsh-soul 的图谱记忆 / 经验编译 | 面向工作流的约束/决策图谱，对陪伴场景过重 |

### 与 hindsight-coding-agents 的区别（社区「项目记忆体」）

有人会问这个编码 agent 的记忆插件能不能替代本插件——**不能，两者解决的不是一类问题**：

| 维度 | hindsight-coding-agents | 本插件（大肥鱼） |
|---|---|---|
| 记忆归属 | 每个**代码仓库**一个 bank（按 git 项目解析） | 每个**匿名用户**一个 bond（跨所有窗口） |
| 记什么 | 项目里"代码里没有的决策"：取舍规则、重试白名单、约定 | 你们之间发生过什么：礼物、心事、话题、情绪、心动 |
| 如何提炼 | **LLM 后台抽取** observations（需 LLM key、花 token、分钟级） | 规则确定性写入 + 模型经工具显式写（零模型调用、毫秒级） |
| 如何组织 | 5 张 knowledge pages（架构/约定/进行中事项） | 时间线 + 长期话题档案 + 六维心境 |
| 如何检索 | 服务端混合搜索 + `reflect` 深检索，首轮注入一次综合 | 词面相关度排序 + `companion_recall`，每回合轻量注入 |

**可借鉴、且已部分具备**：来源标记（hindsight 用 `source:git` / `source:chat` 分开 consolidate；本插件的时间线条目带 sessionId 与类别，可据此区分）、纠错覆盖旧记忆（本插件 `/fish pref` 改口即作废旧偏好）、分层组织（本插件 activities 流水层 + topics 长期层）。

**不建议照搬**：它的 LLM 后台提炼与 reflect 需要额外模型调用，与本插件始终坚持的「零模型调用、不花 token、无静默丢失」原则冲突；而且它是编码项目记忆，不承载角色人格、情绪与亲密关系。它原生支持 dsh（`dsh plugin add @x1a0f3n9/hindsight-coding-agents`），如果你想给**编码工作**也加长期记忆，可以和本插件并存，两者互不干扰。
| longing 的成人维度与渐进解锁 | 明确不做；本插件取其「状态机 + 第一人称注入」的骨架，维度全部换成 wholesome 语义 |
| hippocampus 的 SQLite 多表 | 存储规模没到；现有单表 + 保留分裁剪已覆盖同类语义 |

### 从 surfcore 的记忆卡能借鉴什么（2026-11-20 调研）

[Mieksido/surfcore](https://github.com/Mieksido/surfcore) 的「记忆卡」是给 QQ / B站 / 桌宠共用的角色长期记忆，和本插件是同一类问题（跨会话记得住），但它更重。真正值得借鉴的是下面几条**规则层做法**，而不是它的后台模型调用：

| surfcore 做法 | 本插件现状 | 结论 |
|---|---|---|
| **衰减卡进提示词 + 全量卡只存档**：全量 JSONL append-only、永不注入；衰减卡按预算裁剪 | activities/topics 有半衰期与保留分裁剪，但清掉就没了；`companion_recall` 只能查现存条目 | 最值得补：加一层 append-only 全量流水，召回时按需取，避免「重要但被裁掉」的细节永久消失 |
| **重要度是纯函数 + 可解释理由**（`importanceReasons`：主人私聊 +42、第一次 +30、承诺 +16…） | importance 由各处调用点直接给数字，难以审计 | 可补：把加分理由写进条目，面板可解释「为什么记得这件事」 |
| **四档清晰度**（清晰→清楚→模糊→印象→遗忘），每天最多降一档；被提到会回升 | 直接按保留分排序/删除，不标注确定度 | 已有「大致印象」标注，可进一步做成四档，语气更自然 |
| **确定性「初次相遇」锚点**：首次主人互动 pin 住，不参与压缩 | 里程碑/约定事实上长期保留，但没有「第一次」专门区 | 可补一条 first-meet 里程碑，作为开场与久别重逢的稳定素材 |
| **主动目的机制**：从近期记忆提目标假设（带 owner/confidence/urgency/risk）、驱动向量半衰期、安静时段/每日上限/30 分钟空闲闸/去重 | 当前是打开窗口抢一次开场 + 久别情绪提示，没有持续目的 | 值得分步借鉴；但它的 9 维驱动与后台 LLM 对陪伴插件过重，先沿用规则层硬闸门即可 |

**不照搬**：surfcore 的 embedding / 向量记忆与云服务、以及「模糊化可接模型摘要」都不符合本插件的零模型调用与本地-only 原则；它的多平台 scope 隔离（QQ 私聊不进 B站）在本插件里对应的是**模式隔离**——本次 v0.10.0 已经把能力严格限制在大肥鱼模式。

### 与 MemOS local plugin 的区别与借鉴（v0.15.0 调研）

[MemOS local plugin](https://github.com/MemTensor/MemOS/tree/main/apps/memos-local-plugin) 是本地优先、文件支撑的**通用 agent 记忆系统**，和本插件不是一类东西——它给 agent 装「大脑记忆层」，本插件给角色装「关系与人格」。它原生支持 dsh（ `$DSH_HOME/memos-plugin/` + SQLite `memos.db` + 可选 Viewer），可以和本插件并存。

| 维度 | MemOS local plugin | 本插件（大肥鱼） |
|---|---|---|
| 定位 | 通用 agent 记忆基础设施（跨任意任务） | 单一陪伴角色的关系养成 + 共同经历 |
| 记忆分层 | L1 trace（动作+观察+反思+价值）、L2 policy（跨 trace 归纳的策略）、L3 world model（压缩环境认知）、Skill（结晶能力） | activities 时间线 + topics 长期话题 + 偏好/往事 + 六维心境 |
| 提炼方式 | 后台 LLM 反思 + 奖励反传，高价值模式结晶成 Skill（花 token、分钟级） | 规则确定性写入 + 模型经工具显式写（零模型调用、毫秒级） |
| 检索 | 三层检索（Skill → trace → world model）+ 每轮自动 recall + embedding 语义召回 | 词面概念打分 + `companion_recall`，轻量注入 |
| 反馈自演化 | step/task 级反馈驱动策略自我改进 | 被想起即加固（rehearsal）+ 改口作废旧偏好 |
| 存储/依赖 | SQLite + onnxruntime + 可选 18801 端口 Viewer | 单个 JSON（storageDomain）+ 无外部依赖 |

**v0.15.0 从它借鉴、且落地的关键一条——「查询改写 + 多路召回」**：MemOS 每轮对所有直接用户回合自动 recall，并允许模型用改写后的短 query 再搜（`memos_search`）。本插件此前 `companion_recall` 用**整串子串匹配**，模型问「吃 晚饭 饭」时记忆里明明存着「聊到：吃饭…食堂垃圾食品」却查不到，于是答「没留下」——这正是截图里的问题。现已改为：

- **查询分词 + 概念扩展**：`吃 晚饭 饭` 切成多词，「晚饭/食堂/外卖」统一映射到「吃饭」概念；
- **多路打分**：逐字命中 + 话题概念命中 + 新鲜度/重要性一起排序，不再依赖整串相等；
- **模糊命中标记**：字面零命中但话题档案相关时，工具返回「用『好像/大概记得』口吻」的提示——**承认记得个大概，而不是一口否认**，这是「更像人」的关键；
- **时段锚点**：陪聊摘要带上「早上/中午/晚上/深夜」，解决「食堂那顿是白天还是今晚」的分辨问题。

**不照搬**：L2/L3 的 LLM 反思、Skill 结晶、embedding 语义召回、SQLite + Viewer 都与其「通用 agent 基础设施」定位绑定，需要额外模型调用与依赖，和本插件零模型调用、本地-only、轻量的原则冲突；陪伴关系也不需要「策略自演化」这种面向任务执行的机制。

### 恋人维度：心动是相处出来的

第三条成长轴（与亲密度「亲疏」、心甲「性格态度」并列）：**心动 0–100**。

- **门槛**：亲密度 ≥ 37 且信赖 ≥ 55 后，情侣式表达（情话、告白、约会、牵手）才会推动心动上涨；没到门槛时她会脸红着轻轻挡回去——关系不到，「恋人」不是开口就成立的。
- **档位**：还没开窍（0–29）→ 心动暧昧（30–59）→ 确认心意（60–89）→ 心照不宣（90–100）。注入文本明确告诉模型当前档位该怎么说话。
- **纪念日**：首次跨过 60 会写下「你们确认了心意」的里程碑进跨窗口时间线（别的窗口也知道这件事），并把那天记为纪念日；面板与摘要都会显示。
- **恶意**：辱骂会直接扣心动（按严重度放大），被凶之后想听情话、道歉才哄得好，都和真实恋爱一个逻辑。
- **防刷**：每天心动涨幅有上限（8 点），情话刷屏催不出恋人；心动暧昧之后她还会攒一个「想听情话」的念头，等你来说。
- **尺度红线**（写进注入文本与人设双保险）：亲密表达停留在甜甜的恋爱层面——牵手、拥抱、情话、心跳加速；**不进行露骨描写**。

### 自我评估：含义由她自己判断

规则层（关键词识别、意图倍率）只负责**本能反应**——收到礼物会本能地开心一点、被凶会本能地委屈。但**含义**交给大肥鱼自己认知：

- **同一个行为，不同含义**：为道歉送的礼物不该让她更心动（那是在补疤，不是升温）；口是心非的关心、玩笑里的试探、赌气说的狠话，都由她读出弦外之音。
- **`companion_feel` 工具**：读出表面之下的含义、或真实感受与本能反应不符时，她调用它按真实感受调整亲密度/信赖/心动/六维情绪——**可正可负**，也可以直接修正本能反应的偏差（比如道歉的礼物：好感几乎不动、疙瘩松动）。
- **理由落库**：每次评估必须写明「为什么这么判断」（≤100 字），作为 `feeling` 条目进跨窗口时间线——以后任何窗口问起，她都说得出当初为什么。
- **钳制与防失控**：单次 affection ±10 / trust ±8 / romance ±6 / 情绪每维 ±10；每日自我评估推动的亲密度独立封顶（15）；缺少理由的调用不生效。
- **规则降权**：自我评估开启时，关键词驱动的亲密度加值乘以保底系数（默认 0.6）——本能反应变小，含义判断让位给认知层。恶意惩罚不受降权影响。
- 可用 `selfAssessEnabled: false` 关回纯规则模式（保底系数自动回到 1）。

## 数据与隐私

- **存储位置**：dsh 的 `ctx.storageDomain`，领域 `companion.bonds`，按 `userId` 一行一用户；宿主侧持久化，不进会话日志。
- **隔离键**：默认 `getOrCreateAnonymousUserId()`（每个 dsh home 一个匿名 UUID）。
- **最小化存储**：只存数值状态（含心甲值 `guard`、性格阶段、信赖 `trust`）+ 偏好标签 + 事件摘要 + 经历时间线（每条 ≤120 字引子，含类别、时间戳、会话 id）；**不存对话全文、图片/音频本体、凭据、主机名/IP**。附件只记「分享了图片 / 音频『文件名』」这一句。
- **容量 ≠ 单条字数**：隐私上的"短摘要"指的是**每条**记录的一句话引子（≤120 字），不是全部记忆只有 120 字。全库上限为 `maxActivities`（默认 160 条时间线）+ `maxTopics`（默认 48 条话题档案，每条结论 ≤200 字）+ `maxPreferences`（32 条偏好）+ `maxImportantEvents`（24 条往事）；超出按保留分裁剪、按半衰期遗忘。想让"做过什么"更具体可调大单条引子，想更省空间调小容量上限即可。
- **遗忘也是隐私手段**：超过 2 个半衰期且不再重要的经历会被真正删除，不需要你手动清理。
- **向后兼容**：`guard` / `personalityStage` / `trust` / `activities` 均为可选字段，旧存档读取时自动补齐默认值（心甲 100 / 信赖 50 / 空时间线），不丢数据。
- **文本清洗**：剥离控制字符、折叠空白、按长度截断；数值钳制到合法区间；脏记录由 schema 拦截而不崩溃。
- **用户控制**：`/fish export` 带走全部数据，`/fish forget` 彻底删除。
- **卸载**：服务 / 工具 / 命令 / 监听 / domain 句柄随 fiber 卸载自动撤销，不留运行锁。

## 技术实现要点

- **指令唯一入口**：宿主命令 `fish` + 客户端 `ctx.commandUi.decorate('fish')` 提供 popupSelect 子菜单（官方 feedback / permission 同款机制）。decoration 不制造新行，故无重复；子命令通过 `remote.commands.execute('/fish <sub>')` 交回宿主执行。
- **命令行视觉增强**：dsh 的第三方宿命令行不提供 icon/label（`presentation.ts` 的 `builtinRowFace` 只给 6 个内置命令硬编码图标），故客户端在 `[data-trigger-menu]` 的 `button[role=option]` 上补插鱼图标 + 「大肥鱼陪伴」主标签，并把原 `fish` 降级为灰色别名；子菜单项同样按 label 注入官方风格单色线条 SVG。这层只改显示、不改命令语义，`MutationObserver` 在重渲染后重标，卸载时随 fiber 撤销。
- **命令参数用 `rawInput`**：`CommandDefinition.handler` 收到的是 `CommandInvocation`，参数在 `invocation.rawInput`（`args` 只是 `command/run` 日志事件的字段）。此前误读 `args.args` 导致所有子命令都落到面板。
- **Cordis 4 依赖声明**：函数式插件须在 `apply.inject` 上声明依赖（加载器把 ESM namespace 解包为 default 函数，只读函数对象上的 `inject`）。
- **函数式插件不触发 `[Service.init]`**：domain 在构造函数里主动 `openDomain()` 存为 `this.ready`，所有访问点先 `await this.ready`。
- **工具 schema 用 dsh 的 value schema DSL**：object 节点须声明 `additionalProperties`；必填项是属性上的 `required: true`；`output.render` 返回 `ContentBlock[]`。
- **状态注入走 system prompt，不写会话日志**：关系摘要通过 `ctx.systemPrompt.section({ name: 'companion:relationship', order: 1 })` 提供，在每次请求组装 prompt 时按需求值。它注册在 **agent scope**（`agent.ctx`），`text()` 每次动态检查会话当前 preset：只有大肥鱼模式返回完整摘要（人设行为提示 + 记忆时间线），标准模式返回空字符串（dsh 自动丢弃，不占 token）；agent 销毁时注册自动撤销（Cordis 逆副作用）。
  - **为什么不能 `session.append('user/message')`**：`agent/created` 早于 `turn/start`，此时 surface 为空，注入的 user/message 会占住 surface 首位；等官方 `system/message` 到达时 `protectedHead` 尚未建立，日志被判定 `SessionFormatError: system/message requires a protected first surface head`，**整条会话打不开**。
  - 也不再需要「幂等判据」：不写日志就没有重复注入，`session/end-seed` 重放多少次都一样。
- **会话日志是 fail-closed 的**：读到本构建不认识、且信封没有 `ignorable: true` 的事件类型，dsh 会拒绝解读**整条日志**（表现为「历史加载失败 / unknown to this harness and not marked ignorable」）。养成观察记录必须走 `appendPluginRecord()`（类型用 `plugin:` 命名空间），不能用 `session.append()`。
- **跨窗口记忆 = 事件流水，不是数字推断**：`activities` 时间线按语义写入（送礼 / 谈心 / 故事 / 分享 / 约定 / 里程碑 / 冲突），注入时按 `重要性 × 0.5^(天数/半衰期)` 排序取前 N 条。模型被明确要求「有记录才当事实，无记录就说记不清」，避免从亲密度反推。
- **附件识别靠 content 块**：dsh 的 `ContentBlock` 只有 `image` 与 `file`；音频/视频以 `file` 到达，按 `attachment.mediaType` 或扩展名区分。只发图不写字的消息也要计入互动，所以观察者先看 `collectMedia()` 再看 `text.length`。
- **纯提问不算叙事**：`/fish` 的「我今天有没有送过你礼物？」既不该触发送礼加值，也不该写 story——`detectIntent()` 先用 `isQuestionOnly()` 拦掉。
- **破甲与养成解耦**：亲密度（关系亲疏）与心甲（性格态度）是两条独立成长轴，共用冷却/上限闸门但各自计分；两者都只由情感质量驱动，敷衍与争吵都不涨。
- **可安装性**：bundle 只 import dsh 内置的 `@deepseek-ai/*` 与 `zod`，靠 `peerDependencies` 让 profile resolver 正确路由。
